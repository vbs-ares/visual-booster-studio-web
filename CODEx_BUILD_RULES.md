# Visual Booster Studio — Codex Build Rules

## 1. Project Authority

Every implementation decision must follow this order:

1. Locked Project Documents
2. Approved Design Mockups
3. UI/UX Pro Max Skill
4. User Instructions
5. Codex Implementation

If sources conflict, follow the higher-priority source and explain why.

## 2. UI/UX Pro Max Workflow

Before implementing any UI section:

- Run relevant UI/UX Pro Max search commands.
- Explain which design principles will be applied.
- Compare the approved mockup with those principles.
- Only then begin implementation.

Do not skip this workflow.

## 3. Mockup Policy

Approved mockups are the visual source of truth.

Do not redesign or simplify them without explicit approval.

You may improve accessibility, responsiveness, performance, and semantic HTML.

You may not change visual hierarchy, layout rhythm, premium feel, or component structure without explaining why first.

## 4. Section-by-Section Development

Only one major section may be built at a time.

Each section follows this sequence:

1. Design analysis
2. UI/UX Pro Max review
3. Implementation
4. Typecheck
5. Build
6. Human approval

Only after approval may work continue.

## 5. Premium Quality Standard

Target quality is comparable to Apple, Stripe, Linear, Raycast, Vercel, and Framer.

Avoid generic layouts, template-looking cards, excessive gradients, glassmorphism, and unnecessary animations.

## 6. Technical Standards

- Next.js App Router
- TypeScript
- Tailwind CSS
- Cloudflare Pages compatible
- Static-first architecture
- Semantic HTML
- Accessible navigation
- Dark and light themes
- Mobile-first responsive design
- SEO and AI-discoverability first

## 7. Completion Rules

Every completed section must include:

- Comparison against the approved mockup
- Explanation of intentional deviations
- Confirmation that UI/UX Pro Max guidance was applied
- npm run typecheck
- npm run build

## 8. Approval Rule

Passing builds do not mean approval.

A section is complete only after explicit user approval.
